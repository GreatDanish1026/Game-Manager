GAME MANAGER v1.0.0 - PRODUCTION READINESS PHASE 4

PURPOSE
This phase prepares the actual signed Windows updater assets and latest.json
needed by the Tauri updater.

No application source-code behavior changes are made in Phase 4.

NEW SCRIPTS
scripts\prepare-release-assets.ps1
scripts\verify-release-assets.ps1
scripts\publish-github-release.ps1

STEP 1 - CONFIRM TAURI CONFIG

Your current src-tauri\tauri.conf.json must contain:

"bundle": {
  ...
  "createUpdaterArtifacts": true
}

and:

"plugins": {
  ...
  "updater": {
    "pubkey": "<YOUR TAURI UPDATER PUBLIC KEY CONTENT>",
    "endpoints": [
      "https://github.com/GreatDanish1026/Game-Manager/releases/latest/download/latest.json"
    ],
    "windows": {
      "installMode": "passive"
    }
  }
}

Do not change the existing Tauri identifier.

STEP 2 - BUILD WITH YOUR PRIVATE UPDATER KEY

Open PowerShell in:

C:\Game Apps\Game Manager\Rust\GameManager

Set your signing environment variables in THAT PowerShell window:

$env:TAURI_SIGNING_PRIVATE_KEY="C:\secure\path\game-manager.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD="<your password>"

Then:

npm run tauri:build

For a Tauri v2 Windows NSIS build with createUpdaterArtifacts=true, the NSIS
directory should contain the setup EXE and its .sig file.

STEP 3 - PREPARE RELEASE ASSETS

From the project root:

powershell -ExecutionPolicy Bypass -File ".\scripts\prepare-release-assets.ps1" -Version "1.0.0" -Notes "Game Manager v1.0.0"

The script:

1. Runs the v1 release configuration validator.
2. Finds the newest NSIS *setup.exe.
3. Requires the corresponding .sig file.
4. Copies the installer to:
   release-assets\GameManager_1.0.0_x64-setup.exe
5. Copies the signature to:
   release-assets\GameManager_1.0.0_x64-setup.exe.sig
6. Reads the signature CONTENT.
7. Generates:
   release-assets\latest.json

The generated manifest uses:
platforms.windows-x86_64

and points to:
https://github.com/GreatDanish1026/Game-Manager/releases/download/v1.0.0/GameManager_1.0.0_x64-setup.exe

STEP 4 - VERIFY LOCALLY

powershell -ExecutionPolicy Bypass -File ".\scripts\verify-release-assets.ps1" -Version "1.0.0"

Do not publish unless every local check passes.

STEP 5 - PUBLISH

Manual GitHub method:
- Create a GitHub Release with tag: v1.0.0
- Upload all THREE files from release-assets:
  GameManager_1.0.0_x64-setup.exe
  GameManager_1.0.0_x64-setup.exe.sig
  latest.json

Optional GitHub CLI method:

powershell -ExecutionPolicy Bypass -File ".\scripts\publish-github-release.ps1" -Version "1.0.0"

The publish helper deliberately requires you to type RELEASE before it creates
the GitHub release.

STEP 6 - VERIFY THE PUBLIC FEED

After the release is public, visit:

https://github.com/GreatDanish1026/Game-Manager/releases/latest/download/latest.json

It should display/download valid JSON rather than a 404 page.

STEP 7 - REAL UPDATE TEST

The most important updater test is NOT checking 1.0.0 against itself.

To validate the updater end to end, install a signed build with a LOWER version,
then expose a signed HIGHER version through latest.json.

Example:
installed test build: 0.9.9
remote test release: 1.0.0

Then:
Library Overview -> About -> Check for Updates -> Install Update

Verify:
- new version detected
- release notes appear
- download progress starts
- updater signature validates
- installer runs
- app can reopen
- About displays 1.0.0
- Favorites, Tags, Hidden Games and cached library metadata remain intact

SECURITY
Never upload or commit:
- updater private key
- updater private key password
- environment variable dumps containing the private key

The .sig file IS safe and must be published.
The updater PUBLIC key is safe and belongs in tauri.conf.json.
